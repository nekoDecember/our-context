## 修正した処理

- Gitea 28 の内部向け通知に必要な接続許可を、検証構成と接続ガイドへ記載した。
- 生成するページの必須項目・引用元・参照先を検査する。短いメモの引用は原文の行から選び、JSON Schema の制約を項目ごとに独立させた。
- 日付の回答を対象タスクへ直接反映する。既知の予定と締め切りを追記後も保持する。
- ノートの差分から現在の進捗と解決状況を更新する。
- 相談で関連タスクの状態も読み出す。案件名を保存済み ID に解決し、ガントと報告を同じ対象へ絞る。
- Wiki 点検で引用を検査し、担当・所属などの参照もページの関連として数える。

点検では、他ページからの参照と過去の停止記録について2件の候補が挙がり、進捗を尋ねる確認事項が1件作成された。タスクの現在値は進行中として保持された。

実データのホームと予定をブラウザで開き、予定変更・締め切りの表示を確認した。ブラウザのエラーログは0件だった。

自動テスト30件、模擬サービスを使う統合テスト15項目が成功した。Python の静的チェックと TypeScript・Vite のビルドも成功した。

[実サービスのテスト手順](../tests/e2e/README.md)に起動・接続先・パスワード・終了方法を記載している。社内の Gitea と LiteLLM の接続値は、通常環境の `.env` に設定する。[接続ガイド](connections.md)に設定例を記載している。

通常アプリは検証時に `http://192.168.1.8:8096` で稼働させた。LAN の確認範囲は、この Mac から LAN IP のページと認証済み API への接続である。

通常アプリへ修正を反映し、LAN IP でページ・ログイン・認証済み API の HTTP 200、ワーカーの稼働、既存の参照版の維持を確認した。[稼働確認の記録](artifacts/e2e/main-health.json)を保存した。検証専用のコンテナと推論プロセスは停止済みである。
